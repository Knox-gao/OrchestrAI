## 0. 本里程碑回答的核心问题

**「仅用一句话从零创建一个专属于你的 App」离现实还有多远？**

答：在受控模板域内（任务清单/番茄钟/计数器/速记本），**已经成立**。一句话 → 意图识别 → 真实写盘（6 个文件）→ 真实 `node --test`（子进程、退出码、日志落盘）→ 门禁判定 → 可用的在线预览。生成物是真文件、测试是真进程、预览真能用——全部证据可复查。

关键设计决策：**真实流水线产出与演示剧本同构的事件队列**，通过 `engine.play()` 注入同一引擎——门禁、状态机、UI 渲染零改动复用。这意味着 P4 把模板流水线换成大模型生成时，产品骨架不需要任何变化。

## 2. 协议（如何验证）

- **单元测试**（21 个，`npm test`）：状态机、门禁阻断、事件流重建、审批分支、成本一致性。
- **生成器自检**（8 项，`npm run selftest`）：4 模板 × {正常必须 PASS, 缺陷变体必须 FAIL}，全部真实子进程。
- **GUI 黑盒实测**（浏览器 1600×900）：真实模式全流程 + 缺陷场景 + 生成物独立页签交互验证。

## 3. 实现（P2 增量）

- `apps/server`（零依赖 Node）：
  - 4 个应用模板，每个含：完整功能实现（logic/app/html/css）、真实测试文件（含「缺陷检测点」注释用例）、缺陷变体（字符串替换植入 1 个真实 bug）、修复函数。
  - `runner.mjs`：`node --test` 子进程（60s 超时、无 shell 注入面）、spec/TAP 双格式统计、日志落盘。
  - `pipeline.mjs`：一句话 → spec → 写盘 → 测试 →（失败则退回-修复-重跑）→ 交付事件队列；预算按真实代码行数计。
  - `index.mjs`：`POST /api/generate`、`GET /preview/:id/*`（路径穿越防护）、CORS。
- `apps/studio`：模式选择（真实生成/演示剧本）、预览页签（iframe sandbox）、真实模式徽章、生成错误浮层。
- `packages/core`：`StudioEngine.play()` 外部事件注入口（P2→P4 的关键接缝）。

## 5. 限制（Limitations）与已知问题

1. **模板域生成**：当前 4 类 + 兜底。任意一句话 → 任意 App 需要 P4 的 LLM 生成（接口已就绪）。
2. **测试环境视口限制**：IAB 面板被遮挡时 rAF/setInterval 被浏览器节流——影响自动化观测（回放暂停、计时器不显示走动），不影响真实用户前台使用。
3. 生成 App 的步进输入依赖 blur 触发 change（合成事件环境不触发；真人操作正常，逻辑已被真实测试覆盖）。
4. 主管动作仍未计 AgentRun（沿用 P1 限制，P3 处理）。
5. Windows 特有：`node --test <dir>` 参数语义差异已在 runner 中规避并注释。

## 5. 限制（Limitations）与已知问题

1. **模拟剧本**：Agent 行为是确定性事件流，非真实模型调用（P2 解决）。
2. **主管无 AgentRun**：主管的规划/复核只记日志与门禁，Agent 面板显示「0 次」（P2 让主管也走 run 记录）。
3. **GUI 测试环境备注**：IAB 面板被遮挡时页面 rAF 节流，会导致 Playwright 点击超时——环境因素，非产品缺陷；实测中已通过恢复面板可见性验证。
4. **h4 大写样式**使需求版本号在 innerText 中显示为 V0.1（自动化断言需大小写无关；不影响用户）。
5. 像素角色为 16×16 半身像 + 4 种姿势，行走动画、多角色同屏移动等留待 P1.5。
