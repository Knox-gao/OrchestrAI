# 范式诊断：从模板组合到按需产品开发

- 基线：`711021b`；实验目录：`experiments/openended/`（增量）；正式管线零改动
- 用户判断："还是很模板化，换汤不换药，没有做到真正意义上的按需开发。"
- 研究问题：为什么多轮能力叠加后仍是模板感？当前范式是否应转向按需自主实现？

## 一、执行路径审计（真实源码证据）

真实需求 → `index.mjs /api/generate` → `pipeline.runPipeline` → LLM 意图解析 → **固定模板实例化** → 测试 → 交付。逐层证据：

### 三层枚举封印（模板感的机制性根源，全部已证实）

| 层 | 证据 | 效果 |
|---|---|---|
| ① 类型枚举 | `intent.mjs:7` `KNOWN_TYPES=['todo','pomodoro','counter','notes','gallery','countdown','landing','atlas']` | 需求空间被 8 类瓜分，LLM 只能选桶 |
| ② 布局枚举 | `designbrief.mjs:10` `LAYOUT_ENUM`(7)、`:64` `HERO_ENUM`(4)；`layouts/index.mjs pickLayout` | "创意方向"被枚举封顶，最终落到 2 原语或 pageShell |
| ③ 能力枚举 | `composer/capabilities.mjs:71` `switch(scene.capability)`、`:196 default: throw` | **能力池外直接抛错**——模型不能创造新组件 |

### 关键发现：LLM 在整条管线中从未写过一行代码

对 `generator/*.mjs`、`pipeline.mjs` 的检索证实：**没有任何路径让 LLM 产出 HTML/CSS/JS**。LLM 的全部角色=填参数（intent 字段/Brief 文案/scenes[].params）。Scene Composer 的"创作"= 在 7 个能力的菜单里点菜并填色值——这正是"换汤不换药"的准确定义：**汤（参数/文案/色值）是新的，药（结构骨架）是固定的**。

### 其他审计结论

- `compose.mjs:43` 文档骨架固定（head+场景串+转场区间）；幕数虽 3-5 弹性，但每幕结构=能力函数输出
- "Agent 协作"是叙事标签：`pipeline.mjs` 中 22 处 `agent_state_changed` 全是 `cues.push` 的事件流装饰，**没有独立 Agent 进程/循环/决策**——全部逻辑在单函数里（我方设计如此，为演示语义；但意味着不存在"主管否决重做"的真实机制）
- 视觉迭代：`rendercheck.mjs:154` 自述"不构成视觉质量结论"；真正的视觉评审=我在会话中人工看截图（未产品化）；**不存在对整体创意的自动否决/重做**
- 测试 Agent 只验证预设标准（node --test 逻辑题），无法发现"设计目标本身未达成"

## 三、对照实验（同一需求「拾音角黑胶唱片店」，同验收）

| | A 正式管线 | B 开放式（LLM 自主产代码） |
|---|---|---|
| 链路 | 意图→gallery 模板→采集→舞台图鉴 | 规划(1)+分幕实现(5)+完整性反馈补 JS(3)=9 次调用 |
| 耗时/成本 | 40s | 350s / 29.2k tokens（**≈8×时间**） |
| 结构 | gallery 舞台（第 9 次见同类） | **5 幕全部模型自主命名与设计**（门脸/上新墙/店主选歌/试听预约/来看店），canvas 唱片机视觉+纸感登记条——与 A 结构零重叠 |
| 完整性 | 全交互可用（模板保证） | **初版零 JS**（交互全缺）→ 反馈闭环后预约（唱机 A/B×3 时段+姓名登记）与五类厂牌筛选实测可用 |
| 一次通过率 | 高 | 规划✓；实现 1/5 幕围栏不完整重试；JS 3/3 补齐 |

**结论**：①当前架构确实封死了按需开发（证据链 1-6）；②开放式在 flash 级模型上**可行但必须配执行器护栏**（完整性校验→定向反馈重试——本实验 3 次调用 28s 即修复全部交互缺失）；③代价=时间×8、token×N、需要更严的运行时验证。人工介入：仅修复 agent 脚本自身的解析缺陷（JSON 转义→围栏协议），未触碰任何生成内容。

## 五、目标架构建议（按实施顺序）

**混合范式"护栏内开放式"**——不是在旧管线再加能力，而是换执行模型：

1. **自主规划层**（复用 openended 规划调用）：模型产结构自由的产品方案（无枚举）；现有 Brief/Director 降级为"参考提案"之一
2. **开放式实现层**（openended 分幕协议）：LLM 产真代码；**能力池降级为可检索的参考库**（模型可"参考相似实现"而非"只能选它"）
3. **执行器护栏**（本实验已验证最小版）：完整性校验（每幕必须有 JS、交互元素≥N、无溢出）→ 缺陷定向反馈重试（≤2 轮）→ 仍失败降级到模板路径
4. **成本与安全护栏**：调用预算（如 ≤15 次/项目）、代码黑名单（无外部请求白名单外/无 eval）、沙箱预览
5. **Visual Critic 产品化**：截图→模型评审（已具雏形）→ 结构级问题转"重做该幕"任务（而非只改 CSS）

**Scene Composer 处置**：**降级重构**——`capabilities.mjs` 从"唯一合法结构"降级为参考实现库（检索注入，非白名单）；director/compose 保留为"快速路径"（低预算/简单需求），开放路径为"作品路径"（高表现需求）。**不废弃**：其幕次编排/转场机制/参数质量仍是宝贵的参考实现与快速通道。

**风险与成本**：单项目生成时间 40s→3-6 分钟；flash 模型代码质量方差大（需护栏兜底）；若换更强代码模型，成本上升但通过率上升。**未验证假设**：多轮反馈闭环的收敛率（本轮 1 样本 3 调用收敛）；大页面（>8 幕）拼接一致性。

## 六、决策

**调整架构后继续实验（进入"护栏内开放式"工程化验证）**——不直接全面重写：先在隔离层把第 1-3 项（自主规划+开放实现+完整性护栏）做成可重复跑的生成链（目标：3 个新需求自动全链、零人工、交互全可用），并实测收敛率与预算曲线；达标后再决定替代正式管线的默认路径。
