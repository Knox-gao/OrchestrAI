# Showcase-First 炫技型生成能力实验报告

- 基线：`0ff234a`；实验目录：`experiments/showcase/`（全部增量，正式管线零改动）
- 共用需求：**深海观测站「ABYSS」首屏/完整体验**——高表现力、探索叙事、生物光主题
- 方法：三实质差异方向首屏（真实运行）→ 亲验评审 → 融合选型 → 五场景完整体验 → 两轮实质迭代 → 移动端/技术验证 → 缺口分析与接入方案

## 一、技术栈盘点（以实证为准）

新增实证：**原生 WebGL 点粒子着色器**（14,000 GPU 粒子实时流场积分，Edge headless 与 IAB 双环境运行无 fallback 触发）。已有：Canvas 2D 程序化（体积光束/焦散/海雪/生物剪影）、SVG、滚动驱动、指针/触控、reduced-motion、WebGL 失败回退 UI。未用：外部 3D 库（本轮无需）。

## 二、三方向首屏（experiments/showcase/{cinematic,generative,editorial}/）

| 方向 | 主视觉主体（可指认） | 与主题的联系 | 真实交互（实测） |
|---|---|---|---|
| A Cinematic | 体积光束穿透的水柱+海雪+灯笼鱼/水母剪影 | 下潜的光衰减=电影纵深 | **声呐点击**：脉冲环扩散点亮波前生物（实测 bios=2），HUD 深度/压强/光强实时 |
| B Generative | 14k 生物荧光粒子流场（GPU） | 仿夜光藻应激发光 | **指针搅动**：流场扰动+发光（实测 energy HIGH，回落） |
| C Experimental | 压强排印本身（字距/字重=深度） | 排版即压强可视化 | 标尺跳层（实测浅层 40.8px/200 → 深层 1.24px/700） |

三者空间结构/图形语言/交互逻辑实质不同；全部零外部素材（程序化正当性：光束/粒子/排印各自承载主题语义，非装饰）。

## 三、评审与融合选型（评审者=OrchestrAI 模型亲验，非客观真值）

- A 最具"作品感"：光影纵深+叙事 HUD+探索交互，但首屏信息承载少
- B 技术最强、画面最"活"，但概念单点
- C 概念最原创（排印=数据），静态感强
- **选型：A 为骨架，B 内嵌为第三幕核心交互（观测舱），C 内嵌为第二幕过渡（压强排印）**——三方向不是三选一，而是一部作品的三个乐章。

## 四、完整体验（experiments/showcase/full/index.html，五场景一作品）

S1 潜入开场（光束/焦散/海雪/定场字幕，**滚动=下潜**，HUD 全程联动）→ S2 微光过渡（**压强排印**滚动压缩：实测"光在消失→字被压紧→字字相抵"，字距 40px→3px、字重 200→700）→ S3 观测舱（**WebGL 流场**滚入启动/滚出暂停，搅动发光）→ S4 深渊档案（四条生物数据带）→ S5 海床（沉积剪影+上浮 CTA）。

实测证据：S1 滚动 630m/TWILIGHT 联动 ✓；S2 三阶段+LIGHT 0.4% ✓；S3 canvas 918×592 启动+energy ✓；声呐/搅动全可操作；无控制台错误。

## 五、两轮实质迭代（前后证据：shots/FULL-iters-before-after.png）

**迭代 1（艺术指导层）**：问题=光衰减在长页感知弱/观测舱粒子暗淡/海床空。修复：深度带色温跃变（200/1000m 阶梯）、粒子亮度与体量提升（size 1.5→1.8×、基色提亮）、舱体生物光晕、海床沉积剪影+CTA 呼吸。
**迭代 2（节奏/反馈层）**：问题=S2 三阶段切换过快、S3 能量衰减过疾、声呐无发射反馈。修复：切换点 0.25/0.58+字重先缓后陡（实测中段 weight 463）、能量惯性窗口 2.4→4.2s（实测 3 秒后仍 HIGH）、声呐发射闪点。
两轮均非颜色/间距级调整；改善经亲验+实测确认。

## 六、移动端与技术验证

移动 390×844：无横向溢出（sw=375）、S1 光束/字幕正常、档案单列重组；reduced-motion：S1 cue/焦散/粒子时间冻结均处理（观测舱 uT 固定、焦散跳过）；WebGL 失败回退：fallback 面板已实现（本轮未触发，**未实测触发路径=如实记录**）；性能：观测舱滚出即暂停 rAF（IntersectionObserver），14000 粒子 dpr 上限 1.75。**帧率未量化**（无 instrumentation，局限记录）。

## 七、正式系统能力缺口（代码证据）

1. **Brief 只产"风格描述"不产"视觉装置"**（generator/designbrief.mjs：directions 是文字气质，无 focalObject/场景脚本）——本轮证明"装置+场景幕次"才是高表现力来源
2. **布局原语是静态骨架**（layouts/index.mjs：editorial/workbench 输出一次性 HTML/CSS，无滚动编舞/多幕结构）
3. **图形能力缺位**：管线无 Canvas/WebGL 组件生成能力（atlas/stage 模板是手写特例，非系统能力）
4. **无截图迭代循环**：rendercheck 只判技术门禁，无"渲染→视觉问题→归因→修"的自动循环（本轮全部人工执行）

## 八、接入方案与成本（建议，未实施）

- 方案：新增"Scene Composer"层——Brief 增产 `scenes[]`（幕次/装置/交互叙事），渲染由可组合能力池（2D 装置/WebGL 流场/压强排印/滚动编舞，即本轮四个可复用实现）组装；截图迭代循环先人工后自动化
- 成本估计：能力池抽象 2-3 天·人；scenes schema+校验+测试 1 天；pipeline 接线+回退 1 天；每主题装置库扩充为持续投入
- 风险：着色器能力跨设备（低端机）→ 降级链（WebGL→2D 粒子→静态）；生成时 LLM 选装置的组合爆炸 → 白名单池起步
