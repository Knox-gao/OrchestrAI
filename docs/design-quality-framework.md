# OrchestrAI 设计质量评估框架（阶段三）

原则：**页面高度、图片数量、颜色数量、CSS 复杂度不是设计质量**。每维必须给出"定义 / 检查方法 / 证据"，能自动化的自动化（rendercheck/探针/静态扫描），需要主观判断的保留截图并标注**人工审查**（评分者+依据），不冒充客观真值。

| 维 | 定义 | 检查方法 | 证据形态 | 自动化 |
|---|---|---|---|---|
| A 需求匹配 | 设计是否服务于该需求的真实用户与页面目标（Brief.positioning 逐条对照） | Brief 对照清单：目标用户/转化目标/任务在页面上是否有对应承载 | Brief + 页面区块映射表 | 半自动（映射表人工填） |
| B 艺术指导一致性 | 字体/色彩/图像/图形/空间/动效是否同一方向（对照 Brief.concept 与 artDirection） | 元素抽样：随机取 5 个视觉元素，标注其服务的概念 | 抽样标注表 + 截图 | 人工审查 |
| C 视觉层级 | 第一焦点/标题/内容/操作四层是否清晰可分 | 首屏 5 秒测试（截图）：说出第一焦点；标题-正文字阶比 ≥1.8x 可自动算 | 首屏截图 + 字阶比数据 | 字阶比自动 / 焦点人工 |
| D 构图与空间 | 首屏构图/栅格/留白/密度是否服务内容（对照 Brief.densityBudget） | rendercheck 指标（pageH/视口比）+ 截图网格叠评 | 双视口截图 + 指标 JSON | 指标自动 / 构图人工 |
| E 原创性与辨识度 | 不同项目是否形成各自视觉个性 | 跨项目对比：同位素截图并排，识别度盲评 | 并排对比截图 | 人工审查 |
| F 信息可读性 | 层级/对比度/长文组织/可读性 | 自动：正文与前背景对比度计算（WCAG ≥4.5）；人工：长文滚动组织 | 对比度数值 + 截图 | 对比度自动 |
| G 交互质量 | 交互有明确用途/状态反馈/合理操作 | 关键交互逐项实操 + 状态前后截图 | 操作录迹（前后帧） | 人工实操 |
| H 响应式质量 | 移动端是设计过的自适应（对照 Brief.mobileStrategy） | rendercheck 移动视口 + 溢出检测 + 移动截图人工审 | mobile 截图 + gate JSON | 溢出/加载自动 |
| I 技术可靠性 | 资源加载/控制台错误/横向溢出/导航/可访问性基础 | rendercheck（必需图/溢出）+ visualaudit（按键绑定）+ alt 抽查 | rendercheck.json + audit 摘要 | **全自动** |
| J 性能 | 首屏等待/图片体积/动画负载 | 页面资源总体积统计；截图耗时；动画元素计数（transform/opacity 之外的不合格） | 资源清单 | 半自动 |

**评分约定**：需要打分时使用 1–5 分，必须记录评分者（当前=OrchestrAI 人工审查代行 + 用户终审）、依据引文（指向具体截图区域），并保留分歧不合并。**未执行 = 标注未执行**。

**rendercheck 的边界（重申）**：它只证明 I 维与 H 维的技术部分（渲染成功/必需图加载/无溢出），**不构成视觉质量结论**。
