# 设计基准研究：Solar System Atlas（solar-system-atlas.pages.dev/solar/）

- **审计时间**：2026-10-18（本地时间约 09:20–09:30）
- **浏览器环境**：ZCode 内置浏览器（Chromium 内核），桌面视口 1440×900 与移动视口 390×844
- **方法**：实际访问 + DOM 计算样式读取（可验证事实）+ 点击交互观察 + 双视口截图（见 shots/）
- **证据**：solar-desktop-1440x900-firstpaint.png / solar-mobile-390x844.png
- **限制**：未审计网络层/源码；无法确认所用渲染框架与具体 CSS 实现细节（不做断言）；性能仅观察无量化数据；移动端仅静态观察未逐项操作。

## 一、观察到的设计事实（computed styles / DOM 证据）

1. **色彩**：body 背景 `rgb(5,5,5)`（近黑）、正文 `rgb(231,225,213)`（暖白纸墨）——"档案馆暗底"而非通用深蓝科技风。
2. **字体体系**（DOM fontFamilies 证据）：正文 `Noto Sans SC`；标题自托管 `AtlasSans`（栈含 Inter 回退）；数据/标签 `PlexMono`。三套字体各司其职：标题/正文/数据。
3. **标题排印**：首屏标题「人类造物」`24px / font-weight 300 / letter-spacing 6.72px`——**小字号 + 极细字重 + 大字距**的档案标签美学（与"大字冲击"路线相反，克制即高级）。
4. **渲染形态**：`canvas ×2`、`img ×0`、`svg ×1`——页面视觉主体为程序化绘制，无位图照片；位图（行星贴图）全部在 canvas 内部消费。
5. **内容视角**：首屏标题「人类造物 / HUMAN ARTIFACTS」——本站实际是**太阳系人造物体档案**（航天器图谱），非"行星图鉴"；双语标题体系贯穿。
6. **交互反馈**：点击画面中物件 → 展开上下文档案面板（实测样本："ASTRONOMICAL VOYAGES · 天文学思想长廊"引语面板，含伽利略 1633 引文与"归属存疑"标注）——**点击即获得有出处的叙事内容**，而非仅放大图形。
7. **移动端**：同内容自适应（390px 视口可用，无横向溢出观感），信息架构未坍缩。

## 二、可迁移的设计原则（原创实现验证，不复制其代码/资产）

| 原则 | 事实依据 | 对 OrchestrAI 的要求 |
|---|---|---|
| P1 档案馆排印：细字重+大字距小标题 | 事实 3 | tokens 增加"标题气质"维度（display 字重/字距策略），Brief 的 artDirection 驱动 |
| P2 三字体分工（标题/正文/数据等宽） | 事实 2 | tokens.font 三角色化，数据一律等宽 |
| P3 程序化视觉优先于位图堆砌 | 事实 4 | 图形语言（canvas/SVG 程序化星域/图形）作为艺术指导的一等公民，与图片采集并列 |
| P4 点击即叙事（有出处的上下文） | 事实 6 | 交互必须携带内容价值（引文/数据/来源），不是纯视觉反馈 |
| P5 暖纸墨暗底而非通用科技蓝紫 | 事实 1 | 色彩决策来自主题气质（Brief.concept），禁默认科技蓝 |
| P6 双语信息层级 | 事实 5 | 标题双语（中文主+英文辅）作为档案感排印手段之一 |
| P7 移动端是设计过的自适应 | 事实 7 | Brief.mobileStrategy 必须是显式决策字段 |

## 三、不应照搬的内容

- NASA 行星贴图与专属三维资产；其自研字体（AtlasSans/PlexMono 定制名）；"solar-system-atlas"品牌与页面文案；具体布局像素参数。
- 我们的原创替代：程序化星域/光谱色系（自有实现，atlas v3 已有基础）、开源字体栈（IBM Plex Mono 公开版 + Inter）、原创文案与数据集。
