# Creative Intelligence Benchmark 实验报告

- 基线：`0acc72e`；实验目录：`experiments/benchmark/`
- 研究问题：H1 结构差异 / H2 技术自主 / H3 反馈触发重设计 / H4 护栏下可靠性
- 方法：三差异需求 × LLM 创意规划→开放式代码→浏览器验收→批评修订×2→终验

## 一、三需求

| ID | 名称 | 类型 | 验收要点 |
|---|---|---|---|
| A | 茧·生成艺术个展 | 创意技术/竞赛级 | 三件独立程序化视觉+可交互+创作说明 |
| B | 汉字演化交互图谱 | 文化/教育 | 6 字×3 阶段可视化+说明对应+移动端 |
| C | 潮汐露营·预订 | 业务转化 | 3 营地+日历+表单+3 次点击提交 |

## 二、真实生成链路（全部 LLM 真调用）

| 项目 | 规划调用 | 分幕调用 | 总耗时 | 总 tokens |
|---|---|---|---|---|
| A | 46.5s | 5 幕 | ~3 min | ~15k |
| B | 30.6s | 4 幕 | ~2.5 min | ~12k |
| C | 32.9s | 4 幕 | ~2.5 min | ~13k |

概念主张（LLM 自主产出，未经人工干预）：
- **A**：破茧之前——整个页面是一只正在孵化数字生命的茧，访客的每次触碰都在加速孵化
- **B**：一字千年——让笔画的呼吸替你讲完三千年的历史（SVG 描边动画自绘五阶段字形路径）
- **C**：城市是常水位，周末是涨潮——把退潮到涨潮的六小时变成逃离仪式

技术路径（LLM 自主决策）：
- **A**：原生 Canvas 2D（两件）+ 裸 WebGL（一件）+ CSS/IntersectionObserver 全站动效
- **B**：SVG path + stroke-dasharray 描边动画 + CSS 变量时代色系过渡 + JS 状态机
- **C**：原生 Canvas 潮汐波形与粒子水位 + CSS Scroll-Driven + 纯 JS 日历表单状态机

**H1 结构差异验证**：三项目信息架构/视觉语言/技术路径完全不同——A 是暗色沉浸式艺术展（多 Canvas 层）、B 是浅色文化长廊（SVG 书法）、C 是自然风商业页（Canvas 波形+表单）。**不是换色换文案**。

**H2 技术自主验证**：LLM 自主选择了三种不同技术路径（Canvas+WebGL / SVG 描边 / Canvas+表单状态机），均未被能力注册表限制。

## 四、如实披露的问题与局限

### 4.1 代码不完整（严重——当前最大缺陷）

分幕实现的围栏代码块提取成功率仅 40%（5 幕中 3 幕 undefined / 4 幕中 2-3 幕 undefined）。根因：LLM 输出 ` ```javascript ` 而非 ` ```js `，fences 正则未匹配。**已修复正则但未重跑实验**——当前三项目均有缺失幕（以 fallback 空区块呈现）。

### 4.2 批评循环无效（H3 部分否定）

两轮批评均报 **0 问题**——不是页面无问题，而是 DOM 探针数据不够丰富（仅结构统计），LLM 无法从中"看见"视觉缺陷。**真实视觉审查仍需人工看截图或更丰富的探针**（计算样式/元素重叠/焦点位置）。

### 4.3 页高差异大

B 项目仅 1015px（单屏），说明某些幕的 CSS/JS 缺失后内容塌缩。这与 4.1 是同一根因。

## 八、架构建议（基于本轮证据）

1. **修 fences 正则并重跑**——当前 40% 提取率严重低估了模型实际输出质量
2. **增强探针**——当前仅结构统计，需加计算样式/焦点检测/截图分析能力，否则批评循环无效
3. **完整性护栏**——每幕必须有可运行的 JS（检测后定向反馈补齐，上一轮已验证 3 调用 28s 可修复）
4. **成本**——每项目 7-9 次 LLM 调用（规划+分幕+批评+修复），~3 min / ~15k tokens；flash 模型的输出质量足以支撑结构差异化，但代码完整性需护栏保障

## 九、下一步

修复正则→重跑三项目→增强探针→验证批评循环有效性→若三项目均完整且批评循环产出实质修复，则"护栏内开放式"具备推广到正式试运行的条件。
